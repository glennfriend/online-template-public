## 結構

- 兩個檔案, 各管一件事
    - `data.js`: 所有內容 (`window.CODEFLOW`). 換主題只改這個檔
    - `index.html`: 通用引擎. 結構 + 主題 (`<style>`)、引擎 (`<script>`), 不含任何流程內容
- 引擎依序是: 錯誤顯示、外部相依檢查、資料檢查、畫圖 (版面計算、背景帶、連線、節點、標籤防撞、視角切換)、流程卡片、導讀、尚未查證、縮放
- 互動: 上方按鈕或數字鍵 1~N 切視角; hover 卡片看深層內容; 點流程卡片只留那條路, 再點一次取消; 實際大小 / 符合寬度切換

## 錯誤與外部相依

- 外部相依只有 `data.js`, 寫在 `<script data-global="CODEFLOW">`; 缺了就在頁面最上方列出缺哪個檔案
- 沒有 CDN、沒有網頁字型, 離線可用
- `data.js` 載入時整份檢查 (`validate()`), 有錯就整張圖不畫, 並在頁面最上方一次列出全部錯誤
    - 為什麼不像其他 template 略過有錯的項目: 節點、連線、流程互相引用, 少一個節點會讓連線和流程跟著錯, 畫出來反而誤導
- 流程卡片、導讀、尚未查證 三個區塊各自包在 `guard()` 裡: 某一塊出錯, 只有那一塊顯示錯誤, 圖和其他區塊照常

## 什麼時候用

- 已經追完 code / 訪談完流程, 要讓別人 (QA、PM、新人、客服) 看懂 "為什麼是這樣"
- 一個流程有多種讀法: 使用者看到什麼 / 工程師動到哪 / 哪裡會出事 / 被問到時怎麼回答
- 還沒真的研究懂就不要做. 這個 template 只負責呈現, 不負責猜流程; 沒查證的東西一律進 `openQuestions`

## 三個硬規則

1. 一張圖只有一個骨架. 骨架是 "使用者依序做了什麼" 就整張都是動作; 是 "一筆資料的一生" 就整張都是資料表與作業. 兩種混在一起 = 兩張圖, 分開做
2. 事實與推論分開. 卡片與 `facts` 只放查證過的; 推論寫在 `why` 並講清楚是推論; 沒查證的進 `openQuestions`
3. 沒東西寫就寫 null. 某視角對某節點沒有值得說的, `m.<view>` 寫 `null` (卡片會淡化只留標題), 不要填佔位文字

## 視角怎麼設計

至少 2 個, 建議 3~5 個. 每個視角回答一個問題, 常用組合:

| 視角     | 回答的問題           | colorKey 分類的是                |
|----------|----------------------|----------------------------------|
| 使用者   | 畫面上發生什麼       | 要不要動手 / 只是等待 / 背景發生 |
| 實例     | 帶一筆真實資料走一遍 | 誰在動 (角色)                    |
| Dev      | 動到哪支程式         | 前端 / 後端 / 外部服務           |
| 常見問題 | 被問到時怎麼回答     | 多常被問到                       |
| 風險     | 哪裡會出事           | 風險等級                         |

- 第一個視角是預設摘要來源: hover 的副標題、流程卡片的步驟說明都用它, 所以第一個放最 "是什麼" 的那個 (通常是使用者視角)
- "為什麼" 不放在卡片上 (只有 4 行), 放在 `node.why` (hover 時第一段, 藍框)、`flow.insight`、`primer`
- 只有某個視角要多講的細節 (例如 Dev 的 selector、指令), 用 `views[].extra` 指到節點的自訂欄位, hover 時才追加顯示

## 換資料 (`data.js`)

```jsonc
{
  "meta": {
    "title": "<這張圖在講的流程>",              // 必
    "subtitle": "<一句話: 誰從哪走到哪, 看到什麼>", // 必
    "meta_rows": [["updated_at","2026-08-18 (+8)"], ["scope","..."]]  // 必, 對照用的 key/value
  },

  "views": [                                    // 必, >= 2
    {
      "id": "user", "label": "使用者",           // label = 按鈕文字
      "cap": "要不要動手",                       // 色票列最前面的標題 (這排顏色在分什麼)
      "who": "畫面上實際出現什麼, 按鈕在哪",       // 這個視角是給誰看的一句話
      "colorKey": "actK",                       // 節點用哪個欄位分類
      "labels": { "act": "使用者要動手", "wait": "只是等待" },   // 分類值 -> 說明
      "colors": { "act": "--c-green", "wait": "--c-blue" },     // 分類值 -> 色票 (key 必須跟 labels 完全一樣)
      "extra": { "field": "devNotes", "title": "Dev 細節" }      // 選用: hover 時追加這個節點欄位
    }
  ],

  "nodes": [                                    // 必, 非空
    {
      "id": "pay", "num": "2",                  // num 選用; 主線才給編號
      "col": 1, "row": "main",                  // col 由 0 起往右; row 是軌名 (自己取)
      "title": "送出付款",                       // <= 12 個全形字
      "actK": "act", "sideK": "be", "riskK": null,     // 每個視角的 colorKey 各一個欄位; 沒有就寫 null
      "m": {                                    // 每個 view.id 都要有一筆 (沒內容寫 null)
        "user": ["使用者要動手", "填卡號並送出", "送出後不能按上一頁"],
        "dev":  ["後端", "PaymentController@charge"],
        "risk": null
      },
      "why": "<為什麼有這一步 / 為什麼是這樣設計>",   // 必, hover 第一段
      "facts": ["<查證過的事實>"],                 // 選用, hover 條列
      "devNotes": ["<extra 指到的自訂欄位>"],       // 選用, 名字對應 views[].extra.field
      "ev": ["app/Http/Controllers/PaymentController.php"]   // 選用但強烈建議: 出處
    }
  ],

  "edges": [                                    // 必, 非空
    { "id": "e1", "from": "cart", "to": "pay", "label": "按下付款", "kind": "main" }
  ],

  "bands": [                                    // 選用: 幫每一軌加背景帶與標題
    { "rows": ["side"], "toCol": 1, "label": "前提", "full": "hover 時的完整說明" },
    { "rows": ["main"], "label": "結帳主線 ({n})" }          // {n} 會換成該帶的節點數
  ],

  "flowTags": { "ok": { "label": "主線", "tone": "good" } },  // 選用, tone: good / warn / bad / plain
  "flows": [                                    // 選用: 點一下就在圖上只留這條路
    {
      "id": "happy", "name": "順利付款", "status": "ok",
      "summary": "<一句話這條路在幹嘛>",
      "insight": "<這條路最值得知道的一件事>",     // 選用, 藍框
      "signal": "<出事會看到什麼徵兆>",            // 選用
      "steps": ["cart","pay","gateway","done"],  // 依序; 相鄰兩點之間的 edge 會自動高亮
      "branch": ["e6"]                           // 選用: 額外要點亮的 edge id
    },
    {
      "id": "money", "name": "會出錢的兩個地方", "mode": "set",
      "summary": "...", "nodes": ["pay","webhook"]   // mode=set: 一組節點, 沒有先後
    }
  ],

  "primer": {                                   // 選用但建議: "這張圖是什麼" 導讀
    "title": "這張圖是什麼", "open": false,
    "blocks": [
      { "q": "怎麼看", "p": ["<段落>"], "ul": ["<條列>"],
        "box": { "title": "<最反直覺的一件事>", "p": [], "ul": [] } }   // box = 橘框強調
    ]
  },

  "openQuestions": ["<還沒查證的事, 誠實列出>"],    // 建議寫 (可空 array)
  "labels": { "flows_h": "流程" }                 // 選用: 覆蓋介面固定字串
}
```

- `layout` 可以完全不寫 (欄寬、軌高、軌的 y 由節點內容自動算). 要手調才寫: `{"W":280,"GAP":44,"X0":24,"COLS":10,"rows":{"main":{"y":196,"h":124}}}`
- `data.js` 裡的文字會以 HTML 放進頁面 (hover 卡片、流程卡片、導讀), 所以可以用 `<b>` 之類的標籤; 只放自己寫的內容

## 版面限制

- `m.<view>` 最多 4 行: 第 1 行是分類 (通常照抄 `labels[分類值]`, 會上色), 其餘是說明 (檢查會擋)
- 卡片寬 280px -> 每行約 16 個全形字 / 32 個半形字, 超過會凸出卡片 (檢查擋不了, 自己控)
- `colors` 只能用內建色票: `--c-blue --c-indigo --c-purple --c-teal --c-green --c-orange --c-red --c-pink --c-gray` (淺色/深色模式各有一組)
- `edges[].kind`: `main` 實線 / `side` 淡線 (hover 才顯示標籤) / `gated` 橘色粗線 (有條件才走) / `mutate` 虛線
- 節點在某視角有內容卻沒有分類值 -> 檢查會擋 (顏色會失去意義)

## 寫完自我檢查

- [ ] 骨架只有一種, 沒有把資料流混進動作序列?
- [ ] 每個節點的 `why` 都回答了 "為什麼有這一步", 不是重複標題?
- [ ] 每個視角都真的回答一個不同的問題, 不是同一件事換句話說?
- [ ] 沒內容的格子寫 `null`, 沒有塞佔位文字?
- [ ] 每條 `facts` 都指得出 `ev`; 指不出來的搬去 `openQuestions`?
- [ ] 卡片每行沒有超過 16 個全形字?
